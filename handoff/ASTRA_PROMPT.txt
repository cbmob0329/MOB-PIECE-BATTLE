MOB QUEST v170 内のミニゲーム「MOB PIECE BATTLE」を、独立した縦画面スマートフォンゲームとして新規プロジェクトへ移植してください。

【最重要】
これは「似たゲームを作る」依頼ではありません。
元ゲームに既に存在する MOB PIECE BATTLE のルール、計算、5対5バトルの見た目、テンポ、演出を読み取り、独立版へ忠実に移植する作業です。

添付の reference/mob_piece_reference.js と reference/mob_piece_reference.css は、元の v170 から MOB PIECE 関連箇所を抜き出した参照資料です。
data/figures_master_v170.json と data/tags_master_v170.json も参照してください。

元コードには v96 → v100 → v102 → v103 → v107 → v110 → v115 → v132 → v133 → v136 の上書きパッチが共存しています。
古い定義をそのまま採用しないでください。
「最終的に実行時に有効になっている定義」を優先してください。

特に戦闘表示は v133 の individual 5v5 presentation を基準とし、
v136 の tempo patch を最終テンポとして扱ってください。
v132 の FREE BATTLE / RANK MATCH / CPU / 報酬・ランク処理、
v115 の MOB PIECE 専用ステータス / COST / デッキ重複上限、
v107 以降の 2勝先取・ドロー・交換・配置UIを保持してください。

────────────────────────
■ 今回の目的
────────────────────────

MOB STORY / MOB QUEST の施設内ミニゲームだった MOB PIECE BATTLE を、
単独で起動する「MOB PIECE BATTLE」という新しいゲームの中心コンテンツへ移植します。

今回は以下を完成させてください。

1. 独立版プロジェクトの新規構築
2. 高品質なスマホゲームHOME
3. 現在のMOB PIECE BATTLEの移植
4. FIGURE / DECK / BATTLE の主要導線
5. FREE BATTLE / RANK MATCH の既存機能を動作可能にする
6. 今後の追加機能を入れやすいデータ駆動構造

既存MOB QUEST本体を改造しないでください。
新規プロジェクト側へ必要な処理を切り出してください。

────────────────────────
■ HOMEの品質
────────────────────────

HOMEはWebサイトのメニュー画面に見せないでください。
カードUIを縦に並べただけのプロトタイプは禁止です。

目標は、
「App Store / Google Playで配信されている商用コレクション対戦ゲームのHOME」
として成立する品質です。

MOB PIECE BATTLEはフィギュアが主役です。

HOME画面そのものを、
フィギュアショップ / コレクションルーム / フィギュア展示スペース / バトルアリーナ入口
を感じられるゲーム空間としてデザインしてください。

中央には大きなセンターフィギュア表示領域を置き、
正式な背景透過2Dフィギュア画像を後から差し替えるだけで完成する構造にしてください。

BATTLEはHOMEの最重要アクションとして強く目立たせてください。

MISSION / SHOP / EVENT 等を置く場合も、
一般的なWebカードにせずゲームUIとして処理してください。

過剰なネオン、ガラスモーフィズム、大量のグラデーション、
AI生成Webサイトのようなデザインは禁止です。

カートゥーン2Dフィギュアが映える、
太く、分かりやすく、ポップで商用品質のゲームUIにしてください。

────────────────────────
■ スマホ
────────────────────────

縦画面を基本とします。

基準 390 × 844。

最低でも 320 / 375 / 390 / 430px 幅で確認してください。

safe-area対応。
不要な横スクロール禁止。
主要操作が画面外へ消えないこと。
画像の縦横比を崩さないこと。
PCでは中央にスマホ相当のゲーム領域を表示してください。

────────────────────────
■ 図鑑番号
────────────────────────

元のIDとゲーム内図鑑番号を分離してください。

元IDは sourceId / internalId として保持してください。

表示番号は登録順で、

No.001
No.002
No.003
...

と連番にしてください。

元IDが
1, 2, 3, 14, 53, 56, 11, 4
の順で登録されていても、

表示上は
No.001, No.002, No.003, No.004, No.005, No.006, No.007, No.008
です。

data/figures_master_v170.json にはこのための dexNo / displayNo を用意しています。

■ データ設計
────────────────────────

元ゲームの game.js のような巨大単一ファイルへ戻さないでください。

独立版では責務を分離してください。

例：

src/
  app.js
  router.js

  data/
    figures.js
    tags.js
    battleModes.js

  game/
    deck/
    battle/
    cpu/
    rank/

  screens/
    home.js
    figure.js
    deck.js
    battleSelect.js
    battle.js
    result.js

  components/
    topBar.js
    bottomNav.js
    figureCard.js
    battleHud.js

  styles/
    base.css
    home.css
    figure.css
    deck.css
    battle.css

assets/
  figures/
  backgrounds/
  icons/
  banners/
  effects/

Vite + Vanilla JavaScript + CSS + ES Modules を基本にしてください。

既存ロジックをモジュールへ整理してよいですが、
整理のためにゲームルールや戦闘結果を勝手に変更しないでください。

────────────────────────
■ 素材について
────────────────────────

今回の参照ZIPには画像実体が含まれず、
fig/... 等の画像パスだけが存在する場合があります。

画像が見つからない場合、
勝手に別キャラクター画像へ置換しないでください。

欠けている素材はプレースホルダーまたは明示的なmissing表示にし、
後から同じasset key/pathへ画像を追加すれば自動的に反映される構造にしてください。
