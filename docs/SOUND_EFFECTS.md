# MOB PIECE BATTLE 効果音

設定 →「効果音」でON/OFFと音量を変更できます。「効果音を試聴する」または `#sound` で全31音を試せます。攻撃・スキル・融合は属性、強さ、物理／魔法を選択できます。試聴でゲームの所持品・通貨・デッキ・進行は変わりません。BGMは追加していません。

## 音の対応

| 操作・演出 | キー | 音の役割 |
|---|---|---|
| 選択／決定／戻る／画面移動／エラー | select / confirm / back / navigate / error | 短い打音、上昇音、下降音、低い警告音 |
| デッキ追加／削除／自動編成・アシスト | deckAdd / deckRemove / deckArrange | 追加は上昇、削除は下降、整理は3音 |
| スターター／報酬・交換 | starter / reward | 短い完成音 |
| 開始／ドロー／召喚 | start / draw / summon | 開幕、カードの移動、段階的な立体化 |
| 攻撃／スキル／融合 | attack / skill / fusion | 属性別。スキルは倍音、融合は集結音と低音着地を加える |
| 被弾／防御・攻撃無効／撃破 | hit / guard / defeat | 低い衝撃、硬い盾、崩れる音 |
| ターン開始／バトルフェイズ／終了／位置変更 | turn / battle / end / move | 短い進行合図 |
| 勝利／敗北 | win / lose | 上昇する終止音／下降する終止音 |
| ガチャ確認／集結／予兆／組立／彩色／出現 | gachaOpen / gachaGather / gachaCue / gachaAssemble / gachaInk / gachaReveal | 実際の演出段階で発音。スキップ・閉じると停止 |

連続ドローは既存の演出グループごとに1音です。操作を選んだだけの段階と、成功した召喚・スキル・融合・編成確定を区別します。失敗時は成功音の代わりにエラー音を使います。ガチャの前回結果にも結果表示の短い音が鳴りますが、獲得処理は変更しません。

## 属性と強さ

| 現行属性 | 音色 |
|---|---|
| 火 | 着火ノイズ、下降する火炎、低音着弾、火の粉 |
| 水 | 水しぶきに似た帯域ノイズと上昇する泡 |
| 雷 | 短い高域ノイズの連打と急降下する放電 |
| 地 | 低い振動、岩の衝突、破片 |
| 風 | 柔らかい風切りと細い上昇音 |
| 光 | 高いベルの倍音と輝き |
| 闇 | 下降する低音、不安定な倍音、低域のうねり |
| 無 | 中域の中立的な衝撃と電子音 |

現行の複合属性 `地/闇`、`水/火`、`光/闇`、`闇/無` は、それぞれの構成音を混ぜます。新しいゲーム属性は作成していません。実際の攻撃者に一時的な属性変更がある場合、演出イベントに記録した属性を優先します。

基本の強さはseed→小、middle→中、mob・特殊融合→大です。物理攻撃には短い打撃、魔法攻撃には倍音の持続を加えます。回復を含むスキルは上昇ベルを重ねます。実戦では早送り・演出短縮を含めた実際の演出時間に合わせてPCMを生成し、長い音を一律に重ねません。炎の試聴は小0.82秒・中1.60秒・大3.20秒ですが、戦闘中は短縮されます。

## 再生と保存

- 外部音声ファイルの取得を必要としない独自のWeb Audio合成です。48kHz・モノラルのPCMを必要な時に生成し、AudioBufferを最大40種類までキャッシュします。
- 好評だった炎SEの合成情報を参考にしています。元WAVは未取得で、フィルター・残響まで同一再現した音ではありません。
- PCMにはDC成分の抑制、軽い飽和、頭と末尾のフェードを適用。UI音は低め、重要音のピークは約−8／−6.5／−5.5dBFSです。音量バスとコンプレッサーを通します。
- 初期音量55%。ユーザーのタップ・キー操作後にAudioContextを解放します。既存の明示的な戦闘SOUND OFF設定は初回移行時に尊重します。
- 保存キーは `mob-piece-battle:audio:v1`。ゲームプロフィールの保存キーとは別で、所持数や通貨を変更しません。保存不可でも現在のページ内では設定を反映します。
- 同時発音は最大6音。重要演出を優先し、短いUI音を抑えます。同じ戦闘イベント番号は同一戦闘内で重複再生しません。連打はUI約75ms、重要音約35msの間隔で抑制します。
- 戦闘とガチャに再生範囲を設け、スキップ・終了・画面離脱で該当する残音を止めます。画面が背景へ移った時は全音停止。復帰時は再開を試し、ブラウザが制限する場合は次の操作で再開します。取り逃した音をまとめて後から鳴らしません。
- `webkitAudioContext` も検出します。音声非対応・生成や再生の失敗・保存失敗はゲームの進行を止めません。

## 編集するファイル

`src/audio/synthesis.js` の `CUES` が音一覧、`cueSpec()` が長さと優先度、`element()` が各属性の音色、`fire()` が炎、`synthesizeCue()` が共通音と仕上げです。新しい音を追加する場合はCUESと合成処理を両方追加します。

`src/audio/audio.js` は音量・保存・キャッシュ・発音制限を担当します。`battleSound()` はイベントを音へ変換します。`src/components/battle-director.js` は実際に表示するイベントで再生します。ゲームルール本体への変更は、既存の演出イベントに属性等の参照情報を付加する部分だけです。

画面共通操作と試聴画面は `src/audio/ui.js`。編成・報酬は成功した操作箇所、ガチャは `src/components/summon.js` の演出段階へ接続しています。未使用の旧戦闘画面は現行アプリの導線にないため書き換えていません。

## 検証方法と範囲

`npm run test:audio`：全12属性表記×3演出×3段階、31共通音、ピーク・無音・フェード・物理／魔法差、重複発音、6音上限、保存、ミュート、非対応、背景移行、終了処理を検証します。

`npm run test:audio-ui`：起動中のサーバーへEdgeで接続。標準URLは `http://127.0.0.1:5187`、別URLは `MPB_TEST_URL` で指定できます。試聴、音量・ミュートの再読込、実際の戦闘操作、再戦と離脱、音声非対応を検証します。OfflineAudioContextで実バスのPCM出力とミュート時の無音も確認します。

Headless Edgeのブラウザ試験と、背景移行のシミュレーションです。iPhone/iPadの実機Safari、各端末スピーカーでの聴感、Bluetooth機器固有の遅延は未検証です。試聴ページで端末に合う音量へ調整できます。
