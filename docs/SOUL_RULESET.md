# SOUL FUSION update (2026-10-02)

最新のユーザー指定により、独立版の現行対戦は旧25体・5vs5オート・タグ最終パワー方式から置き換えた。handoff/README_FIRST.md の旧戦闘維持指示より今回のユーザー指示を優先する。MOB STORY（別リポジトリ MOB-QUEST）のゲーム・モブピースバトル・データは編集していない。

## 現行仕様

- デッキはシード30・ミドル10・MOBソウル5。通常ドローはシードだけ。ミドルとMOBは専用領域。
- レア度 `rarity` と階級 `soulClass` は独立。能力 `atk` / `def` は保存された固定値。
- 初期ライフ400。場3枠。空き枠がある限り召喚回数制限なし。
- ターン開始時、手札5になるまで補充。必要枚数を引けないと山札切れ敗北（ユーザー追加回答）。手札5なら山札0でもドローしない。
- シード2→ミドル、ミドル2→MOB。専用領域の対象とレシピが必要。使用素材は墓地へ。
- 各プレイヤー、各ターンにスキル1回。使用者は同ターンに融合素材不可、攻撃は可能。
- 相手ターン対応の防御・回避・反撃・復帰は相手メイン中に準備する。バトルフェイズでは新たなスキル発動不可。準備した効果の解決は新たな使用回数を消費しない。
- バトルへの移行は一方向。召喚・スキル・融合はメインのみ。通常攻撃は各駒1回、対応スキルで回数加算。
- ATK > DEF のみ撃破と差分ライフダメージ。直接攻撃なし。全体攻撃・反撃もフィギュア間の比較で処理する。
- 無指定のシャッフル・会心・確率回避などは導入せず、シードの編成順でドロー。スキルのバフ・妨害・待機効果はそのターン終了まで。回復は400まで。
- タグは分類と融合条件に利用し、旧タグパワー・隣接倍率を適用しない。原典タグからレア度別上限以内を採用。

## 原典と性能設計

`scripts/build-soul-catalog.mjs` が別リポジトリを読み取り、`src/data/soul-catalog.js` に固定設計データを出力する。戦闘時に能力値を生成・抽選しない。

327体すべてを現行のフィギュア定義（装備効果・特性・ソウル・タグ・レア度）と照合。対応する原キャラクターも一意に確認できた168体は、原典の役割・ATK/MAG/DEF/SPD・技・パッシブ等を併記する。プレイヤーフィギュアは同名の敵ではなくパーティーデータを優先。

実行データの基準は保存済みv248データ。v249のHP調整、v250のアクション数・軽減・回避の変更を原典のソースと照合し、対象ボスの変更値を保持。新作ではHPを使わないためHP倍率をATK/DEFへ単純転写しない。専用キャラクターと照合できないロゴ・コラボ等は、原典フィギュアの明記された性能を根拠とし、架空の戦歴を補わない。

役割とスキル強度から範囲内の固定値を設計。防御・回復系はDEF寄り、攻撃系はATK寄り、多段・全体・復帰・回避系は基礎値を抑制。スキルは主効果を中心に確定量へ翻訳し、旧RPGの全効果をそのまま複製しない。元効果と翻訳内容は一覧に併記する。

形態が明確なホーク／ミラモブ／ガーディアンのⅡ形態、ミント／マカロンの変身には専用レシピを用意。その他のレシピは原典の種族・シリーズタグと属性から設計。新作専用の汎用レシピも根拠欄で区別して表示する。

参照ファイルとSHA-256は `docs/soul-source-audit.json`。性能データの元資料・役割判定は各行の `source` に保存。

## 保存と画面

現行の5デッキは `profile.soulDecks` / `soulDeckSlot`。旧セーブの所持、ガチャ、通貨、展示、進行を維持し、旧デッキはバックアップとして残す。新しい45体編成を勝手に旧25体から補完しない。

HOME・FIGURE・DECK・BATTLE・ガチャ性能詳細を接続。既存大会の進行・報酬に新バトルの勝敗を渡す。現行対戦の入口は `screens/soulRuntime.js`。旧 `battleRuntime.js` と旧ルール関連ファイルは過去資料・旧セーブ検証用に残るが、対戦画面から起動しない。

一覧は `figure-catalog.html`。データをHTML内に埋め込み、レア度・属性・タグ・階級・能力で並び替え、名前・スキル検索、タグ絞り込みが可能。画像はリポジトリの相対パス。ファイルを別の場所へ持ち出す場合は画像フォルダも同じ構成で配置する。ビルドには同じ一覧を `public/figure-catalog.html` から同梱。

## 開発

`node scripts/build-soul-catalog.mjs` → `node scripts/export-soul-html.mjs` で再生成。原典参照パスはスクリプト先頭。個別調整時はジェネレーター側も更新する。

`node scripts/soul-rules-check.mjs` でデータ範囲・所有・フェイズ・融合・スキル・攻撃・山札切れ・決着を検証。従来テストも回帰確認として維持。
